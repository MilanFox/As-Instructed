**Verdict:** fixed

**Findings:**

1. **An early latch is permanent, and the fact card said it was only "uncounted".**
   *What is hidden:* `latchAudit` puts a station into `bad` the moment it is switched `off -> on`
   while its feeder is still `off`, and `bad` is never cleared. `orderedCount` is
   `good.has(id) && !bad.has(id)`, so once a station has been latched early **no later sequence of
   `use()` calls can make it count again** — the run is unwinnable from that tick onward.
   *What grades it:* the `in-order` objective (`src/levels/world-5/w5-01.ts:250-258`), via
   `orderedCount` (`:150-153`) and `latchAudit` (`:76-102`).
   *How a player hits it:* the Latching fact read `use() flips a substation on either way. It only
   **counts** if the machine feeding it was already on.` — which describes a per-flip test, not a
   permanent mark. The obvious repair is "switch the feeder on, then cycle the station off and on
   again in the right order". Verified against the engine: driving seed 1 as (latch `sub-2` early)
   → (latch `sub-1`) → (`use` `sub-2` twice, ending `on`) → (rest in order) leaves **every**
   substation `on`, `energised` passes, and `in-order` still fails. The divergence is legible
   (`tick 4 · sub-2 / sub-1 already on / sub-1 was still off`), so the player is told *where* — but
   the rule that no repair exists was stated nowhere. DESIGN §11.1.
   Note the objective title ("Latch each substation only after its feeder is live") did state the
   strict rule; the fact card contradicted it. The fact card is the one the player keeps on screen.
