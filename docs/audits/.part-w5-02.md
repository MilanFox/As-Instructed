### The declared exception — VERIFIED, the brief does say so

DESIGN.md §11 licenses w5-02 to withhold the break's position "when uncovering it **is** the
level's stated question … In both the brief says so." The brief (`w5-02.ts:99-109`) carries all
four pieces in player-facing text:

- *something is withheld*: "two hundred segments long and one of them has failed" — the count is
  given, the identity is not;
- *uncovering it is the ask*: "Find the broken segment and patch it.";
- *uncovering it is rationed, and the ration is arbitrary rather than derivable*: "The test set is
  rated for ten readings per shift. It is rated for ten readings because it is rated for ten
  readings.";
- and the `Readings` fact (`:126-129`) closes the side doors: "Ten `probe` calls for the whole
  shift, **whatever you point them at**. Nothing else reports continuity."

That last clause is load-bearing and true. I checked the alternatives: `TileView`
(`src/engine/sim.ts:60-71`) carries `machineId` but no `vars`, so `scan`/`look` cannot read
`live`; every tile in the run is `Terrain.Cable` including the broken one, so there is no visual
tell; every relay ships `state: 'open'`, so machine state does not leak it either; `use` on a
relay always returns `false` (no `cycle`) regardless of `live`; and `world.vars.breakAt` is not
reachable from any player API and is not rendered anywhere in `src/ui/`. Sensing really is the
only channel, and it is the only channel the facts claim.

So the sensing mechanic is left alone, as instructed. Everything else audited normally:

- **Probe budget stated?** Yes, twice — the brief ("ten readings per shift") and the `Readings`
  fact, which also states the part that actually bites: probes at non-relay ids and probes that
  return `null` still count. `Objectives.withinSenses` counts every `sense(bot, 'probe', …)`, so
  the fact matches the predicate exactly. The over-budget divergence is
  `probe() / 10 calls / N calls` — a plain number, nothing about the break.
- **The break's definition stated?** Yes: "`probe(id).vars.live` is `1` while the run is still
  whole that far and `0` once it is not. The first `0` is the break." That is both halves of what
  makes bisection legal — the value's meaning *and* its monotonicity — and it matches
  `build`'s `live: index < broken ? 1 : 0` including at both endpoints. The uniqueness guarantee
  ("one of them has failed") is in the brief, which is what lets the reference answer `low`
  without ever probing `relay-199` on seed 3.
- **Hints introduce nothing.** Hint 1 (a reading tells you which side) and hint 3 (1,1,1 then
  0,0,0, never back) both sharpen "still whole *that far* … `0` once it is not", already on the
  fact card. Hint 2 is the budget arithmetic. Three distinct blockers, no repetition worth
  flagging under CURRICULUM §2.11.
- **Divergence messages.** Wrong count: `relays patched / exactly 1 / 2: relay-0, relay-1` — names
  the strays. Nothing patched: `relays patched / exactly 1 / (nothing)`. One wrong patch:
  `where` is the relay id, and the pair carries no number and no direction word. The withholding
  here is exactly the licensed one, and §11.6's "name the value at fault" is still satisfied — the
  run's own answer is named back to it. `divergence.test.ts:134-145` pins the no-leak property
  (`not.toMatch(/\d/)`, `not.toMatch(/before|after|higher|lower|past/)`) and is correct as written.
- **Seed 1 degenerate?** No. `BREAK_AT` is a frozen table, not a draw: seed 1 = 97 (mid-run, not a
  midpoint of any bisection — `(0+199)>>1` is 99 — so "probe the middle and patch it" fails
  immediately), and the two degenerate cases CURRICULUM §7 asks for sit at seeds 2 (index 0) and 3
  (index 199), never first. The comment at `:26-30` says exactly this. A search written over
  `[1, 198]` passes seed 1 and dies on seed 2 — the fair kind (§11.4): the endpoints were named on
  the fact card, the run just didn't cover them.
- **Bonus title vs predicate.** `eight-probes` is labelled "Locate the break using at most 8
  probes" and its predicate is only the count — but stars are banked only on a passing run
  (`src/game/store.ts:769`), so "locate" is enforced by the run and the label is honest. 8 is the
  information-theoretic floor (`ceil(log2 200)`), reachable and stated.
- **Reference verified against every seed:** passes 1–5, 2 ticks each (par 2, `graded: false`),
  probe counts 8 / 8 / 7 / 8 / 8, and it takes `eight-probes` on all five.
- **No hidden budget.** No `costs` or `budget` override; defaults are 20 000 ticks / 2 000 000
  ops, so even a 200-probe linear scan finishes and fails legibly on the probe objective
  ("200 calls") rather than dying on an op limit.
- **`__tests__` encode no defect.** `divergence.test.ts:103-145` is the only w5-02 coverage in the
  two files I was given and it asserts the shipped behaviour; `bonus.test.ts` is entirely w5-05.

**Changed:** nothing.

**For the user:**

1. **The `eight-probes` star is close to confetti.** Any textbook bisection over `[0, 199]` costs
   exactly 8 probes worst case, so the star lands on every correct program — the required
   objective's 10 leaves only 2 probes of slack for a sloppier search to spend. `bonus.test.ts`'s
   own header calls a bonus every passing run collects confetti.
   *Recommendation:* leave it. Tightening to 7 would make the star unreachable (7 probes cannot
   separate 200 candidates), and loosening the required objective is a budget change I am told to
   report rather than make. If you want it to bite, the honest lever is raising the required
   objective to ~12 so a linear-then-bisect hybrid still closes the order but misses the star —
   that is a budget change, your call.
2. **Seeds 4 (41) and 5 (158) are close to CURRICULUM §15.4 padding** — they differ from seed 1
   only in the number, not in a decision the program has to make. I did not touch them: CURRICULUM
   §7 mandates 5 seeds for this level, and 158 is the only case that lands strictly above the
   midpoint of the first bisection, so it does exercise the other branch. Flagging, not
   recommending a change.
3. **Trace legibility (CURRICULUM §2.6) is met only via `print`.** The probe sense events record
   *which* relay was read, not what it read, so a player debugging an off-by-one has to print
   their own readings. That is the same withholding the exception licenses and I would not change
   it — noting it because §2.6 and §11's exception pull in opposite directions here and w5-02 is
   the place they meet.
